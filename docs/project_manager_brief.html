1. Executive Summary & Core Product Architecture

Vyora is an all-in-one cloud billing, receivables, supplier payables, and traceable inventory management platform purpose-built for Indian micro, small, and medium enterprises (MSMEs). Our core mission is delivering data security, rapid user adoption, Theme B (Teal Ledger) visual clarity, and flawless concurrency stability (1,000 to 50,000+ tenants) without over-engineering.

vyora-backend (REST API Core) NestJS 11 + Mongoose 8

Stateless modular API. Enforces tenant boundaries via TenantGuard, role controls via RolesGuard, and quota limits via PlanGuard. Minor currency integer precision across ledgers.

vyora-frontend (Web Admin App) React 19 + shadcn/ui + Vite 6

Responsive SPA built on Theme B (Teal Ledger), Radix UI popovers, shadcn/ui Table suite, and Toast feedback. Debounced search, edge-to-edge modal footers, and icon-only table actions.

High-converting marketing hub featuring live pricing plans, SEO blog articles, and 10 interactive utility tools (QR generator, GST calculator, currency converter, HSN finder, loan EMI).

vyora-mobile (Mobile POS & Billing) Flutter / React Native Monorepo

Upcoming cross-platform counter app consuming the exact same NestJS backend and APIs via shared types, Bearer JWT authentication, and local offline cache.

2. Roles & Rights: Analysis of the Demotion Issue & Clean Resolution

In the recent team management audit (referenced in user incident screenshot media_1791700339539_0dcc8fac.png), a business owner attempting to demote a secondary team member from Owner to Staff encountered the blocking error:

Observed Error: "Cannot demote the last remaining owner. Assign another owner first."
Context: The business had 2 total members — both marked as Owners (Rahul Sharma as "Primary Owner" and Sandip Yadav as "Owner"). When Rahul Sharma toggled Sandip Yadav to Staff, the request was rejected.

Root Cause Analysis

  • Collection Query Disconnect: The backend rule in business.service.ts checked membershipModel.countDocuments({ businessId, role: 'OWNER', isActive: true }).
  • Legacy & Undefined Field Exclusion: In MongoDB, querying { isActive: true } strictly filters for documents containing explicit boolean true. Seeded records or memberships created before the schema update had isActive: undefined, causing MongoDB to count only 1 active owner instead of 2.
  • Primary Owner vs Promoted Owner Disregard: The database stores the root account creator inside business.ownerUserId. The primary owner is permanently immune to role changes. Therefore, even if all secondary owners are demoted to Staff, the Primary Owner always remains, guaranteeing that a business is never left without an owner.

The Robust V1 Invariant Rule & Architecture Fix

User Type Immutability Status Promotion / Demotion Permissions
Primary Owner
business.ownerUserId		 Permanently Immune • Can promote any Staff member to Owner anytime.
• Can demote any promoted Owner back to Staff anytime without triggering the "last owner" block.
• Cannot demote or delete their own primary account.

role: 'OWNER' in Membership		 Full Workspace Admin • Full access to invoices, catalog, purchases, payments, and reports.

5. Competitor Strategy: How Vyapar Manages Roles & What Vyora Does Better

How Competitor "Vyapar" Operates Desktop-First Legacy
  • Role Presets: Offers Admin, Salesman, Biller, CA/Accountant, and Delivery Boy.
  • Binary Restriction Checkboxes: Uses simple toggles: "Can see purchase prices? NO", "Can edit old invoices? NO", "Can give discounts? NO".
  • Local-First Sync: Runs on a local desktop database that syncs to cloud drive, leading to sync conflicts when multiple devices write simultaneously.
Vyora's Enhanced V1 Strategy Cloud-Native Modern
  • Zero Sync Conflicts: Real-time cloud persistence with optimistic locking on MongoDB Atlas.
  • Module Hiding: If an operator doesn't need Reports or Purchases, the navigation link completely disappears — zero distraction or confusion for staff.
  • Instant Role Switchboard: 1-click active/suspend and role switch toggles without requiring manual app re-installation or complex permissions wizards.

6. Billing Management & Secure UPI QR Code Flow

Billing occurs across two distinct domains: Subscription Billing (tenants paying Vyora) and Customer Invoicing Billing (buyers paying tenants). Both must adhere to secure, standardized payment flows.

A. Subscription Checkout & Missing QR Fix

Resolution for Subscription Modal UPI: When users select UPI/QR in PlanPurchaseModal.tsx, instead of showing a blank state, the system renders a dynamic Bharat UPI QR code encoded with merchant VPA, exact plan amount in minor units, and unique idempotency reference.
  • Standard Indian VPA Format: upi://pay?pa=vyora.billing@icici&pn=Vyora%20Cloud&am=2999.00&tr=TXN_98231&cu=INR
  • Production Payment Gateway (Roadmap): Integration with Razorpay / Cashfree Standard Hosted Checkout for automatic webhook reconciliation, recurring renewals, and automated GST input tax credit (B2B Tax Invoice generation for the subscriber).

B. Counter Invoicing Dynamic UPI QR Code

  • Per-Invoice Dynamic QR: When a counter cashier creates a sales bill, the app displays a dynamic QR code on screen or prints it on thermal/A4 invoices.
  • Automatic Settlement Tagging: Customer scans with Google Pay, PhonePe, or Paytm. Cashier clicks "Payment Received via UPI" to generate an idempotent payment voucher and mark the invoice paid.

8. Cross-Platform Mobile App: Architecture Consuming the Same Backend

The user requested: "i want to create a seprate mobile app and want to use the same backend and api so how we can manage this this is possible or not".

Architectural Verdict: 100% Possible and Recommended. The Vyora NestJS backend is completely decoupled, stateless, and REST-compliant. Both Web and Mobile consume the exact same backend endpoints without code duplication.
Shared Monorepo Foundation @vyora/shared-types

Data models (Invoice, Product, Party, PaymentRecord) and validation schemas live in shared monorepo packages. Mobile app directly imports the same contracts.

Authentication & Device Security JWT Bearer + Refresh Token

Mobile uses the same /auth/login endpoint. Access tokens stored in EncryptedSharedPreferences (Android) / Keychain (iOS) with biometric unlock (Fingerprint / Face ID).

Offline Counter Billing (Inspired by Vyapar) High-Value Mobile Capability

Indian retail counters frequently experience spotty internet. By integrating a local SQLite / WatermelonDB cache on the mobile device, cashiers can generate bills offline. Bills queue locally and automatically sync to MongoDB via idempotent endpoints (idempotencyKey) as soon as Wi-Fi/4G reconnects.

10. Concurrency Stability, Security & Data Protection (1k - 50k Users)

Indian billing platforms must never crash during month-end or festive shopping surges. Vyora integrates enterprise stability controls:

  • Sliding-Window Rate Limiting (rate-limit.middleware.ts): Restricts auth endpoints to 25 req/min (anti-brute-force) and general API endpoints to 200 req/min. Sweeps memory every 10 minutes to support 50k unique IPs without leaking heap.
  • Client Search Debouncing (SearchInput.tsx): 300ms debounce eliminates query hammering while users search products, invoices, or parties.
  • High-Capacity Data Table Architecture (<Pagination> + Table.tsx): Virtualized page chunks (10, 25, 50, 100) ensure zero browser freezing even with 50,000+ customer records.
  • Zero Floating-Point Ledger Precision: All currency stored in minor integer units (paisa) prevents rounding drift across multi-line tax calculations.
